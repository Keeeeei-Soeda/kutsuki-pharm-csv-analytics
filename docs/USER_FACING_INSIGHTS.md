# ユーザー目線の示唆：現状分析

> 目的：Python側で深く出した分析結果が、**実際の利用者（薬局長・スタッフ）に届いているか**を、画面に出ている文言だけで評価する。  
> 対象UI：薬局向けレポート（`docs/` / GitHub Pages）。学術用凍結版は対象外。  
> 調査日：2026-10-19（`design-d` ブランチの HTML を実測）

---

## 1. 一言でいうと

**「読める日本語の結論」までは出せている。でも「月曜に何をするか」までは足りない。**

深いモデル（GLM・条件付きロジット・ITS・生存分析など）は、だいたい **専門家向けの折りたたみの中** に閉じている。  
薬局長が最初に見る層は、結論ボックスと図の一言キャプションで、ここは意図どおり平易になっている。

問題は「わかりにくい専門語」より、**わかったあとに手が止まる粒度**にある。

---

## 2. 想定ユーザーと、彼らが見る順番

| 想定ユーザー | 見るもの | 欲しい答え |
|---|---|---|
| 薬局長・経営判断者 | トップの経営サマリー → 各Phaseの結論ボックス | いま何枚？良い？悪い？次に何をする？ |
| 現場スタッフ | 具体リスト（どの医院・どの町）・地図 | 今日・今週の動き |
| 分析担当・社外コンサル | 専門家向け折りたたみ | 前提・N・手法・限界 |

いまの設計は **上2人向けに表を書き換え、下1人向けに折りたたんだ** 形になっている。方向性は正しい。

北川氏側の課題認識（`docs/ui_benchmark.md`）は「刺さるが行動に繋がらない」。  
現状評価も、まさにこの軸で切るのが妥当である。

---

## 3. ユーザーに実際に見せている3層

### 層A：トップ（`index.html`）— 経営サマリー

ファーストビューに、次の3ブロックがある。

| 見出し | 中身（現状の実測値） | ユーザーが受け取れるか |
|---|---|---|
| いまの状況 | 月1,768枚／目標3,000まであと1,232枚／門前1%・上位2院73%／90日再来41% | ◎ 数字だけで状況がわかる |
| わかったこと | 2院依存／徒歩圏52%／急性科→内科へ広がらない（11%） | ○ 構造はわかる |
| 次にやること | ①門前以外（特に内科）との関係づくり ②初回の再来働きかけ ③施策を測れる形で | △ 正しいが抽象的 |

注意：トップの「次にやること」3行は `src/build_summary.py` に**直書き**で、各ページの結論ボックスと完全同期していない。

### 層B：各ページ冒頭の結論ボックス（わかった／良い悪い／次）

Phase 1〜6 と来院経路にある。地図にはない。

型はユーザー向けとして優秀である。

1. **わかったこと** … 事実（数字つき）  
2. **良い？悪い？** … 判断  
3. **次にやること** … 行動の方向

### 層C：図の一言（`fig-point`）＋オープンな表・図

「この図を見たら何がわかるか」を図の直前に置いている。  
専門家向けの中の図には、ほぼ付いていない（閉じているので優先度は低い）。

- Phase 1・4 は、開いている表に医院名があり、行動に一番近い。

## 5. ユーザー目線の評価（理解 × 行動）

薬局長が30秒で開いたときの想定。

| 問い | 現状 | 判定 |
|---|---|---|
| いまの処方箋は足りているか | 1,768 vs 3,000、あと1,232枚 | 理解できる |
| うちの店は門前か | 40m門前は1%。近い2院に73%の近接型 | 理解できる（定義を読めば） |
| どこが危ないか | 2院依存・再来41%・急性→内科に広がらない | 理解できる |
| チラシは効いたか | 「判定できない」＋理由＋次の測り方 | 理解できる（やや長い） |
| 月曜に誰のところへ行くか | 「上位10件」「内科系」「新しい処方元」 | **ここで手が止まる** |
| チラシをどこに何枚配るか | 千里丘西・西駅前町までは出る。枚数・期間なし | 半分止まる |
| 初回の声かけを誰から試すか | 「再来率の低いクリニック経由」→表はあるが結論に医院名なし | 半分止まる |
| 3,000枚にどう届くか | 「新処方元が必要」「延長では最大2,312」 | 理解できるが計画に落ちない |

**理解度：おおむね合格。行動変換：不合格寄り。**

Pythonの深さ（空間・選択・定着・因果・予測）は、ユーザー層ではほぼ「結論の根拠の倉庫」になっている。倉庫としては機能している。店舗オペレーションの指示書としては、まだ足りない。

## 6. 「深い分析」と「ユーザーが見る文」の対応

| Python側でやっていること（例） | ユーザーが実際に見る文 | ギャップ |
|---|---|---|
| 地区集計 binomial GLM・距離減衰 | 「来局をいちばん左右するのは距離」 | 手法名は消えている。良い |
| Growth シミュレータ | 「延長では3,000に届かない（最大約2,312）」 | 天井は伝わる。候補医院が結論にない |
| 条件付きロジット・Huff | 折りたたみ内 | ユーザーは触らない |
| 90日定着・コホート・生存 | 「90日再来41%」「医院で最大26pt差」 | 差は伝わる。優先医院名が結論にない |
| 差の差・比較ITS・プラセボ | 「判定できない」＋記録の仕方3点 | 誠実。効きそうな施策の順位はない |
| 急性→慢性遷移 | 「11%で広がっていない」 | 戦略の芯。内科の相手が無名 |
| メッシュ・Moran・競合圧力 | 折りたたみ／地図 | 地図に結論ボックスがない |

ユーザーにとって意味があるのは、**手法ではなく「店の構造」と「次の一手」**である。  
いまは前者の要約までは到達し、後者の**指名（誰・どこ・いつ・どう測る）**が薄い。

## 7. 画面に既にある「使える具体」と、結論に乗っていないもの

### すでに開いている本文にある（使えば動ける）

- Phase 1：関係づくり候補の表（門前以外・処方箋多い順・医院名）
- Phase 2：近いのに来局が少ない地域の表（町名）
- Phase 4：クリニック別の再来率の表
- Phase 5：施策ごとの「確認できた／できない」表

### 結論ボックスやトップには乗っていない（だから見落とされやすい）

- 候補医院の**具体名**（「上位10件」で止まる）
- 再来率が低い医院の**具体名**
- 内科系の**優先医院**
- 配布の**枚数・期間・測り方**（地域名だけ）
- 2院依存のリスクを**枚数で示したシナリオ**（片方半減したら何枚減るか、など）

つまり、**データはあるのに、一番目立つ「次にやること」行に上がっていない**ケースが多い。

## 8. ユーザーが混乱しうる点

1. **門前1% vs 「門前型」イメージ**  
   40m定義では門前はごく少ない。近い2院への依存が実態。定義を読まないと「うちは門前じゃないのか」と混乱しやすい。

2. **Phase名とサイドバー説明**  
   「来局率と成長余地」などは、まだ分析用語寄り。見出し（headline）は質問形で改善済み。

3. **「判定できない」＝効いていない、と誤読**  
   Phase 5 は文で否定しているが、結論だけ眺めると誤解されやすい。

4. **地図にまとめがない**  
   視覚的に一番「わかる」ページなのに、示唆がない。見て終わりになりやすい。

5. **フィルタ準備中**  
   サイドバーに期間・区分フィルタ枠があるが未実装。期待して触ると空振りする。

## 9. ユーザーにとっての「意味がある示唆」の定義（このプロジェクト用）

次を満たす文だけを、ユーザー向け示唆とみなす。

1. **事実** … 数字と期間がある  
2. **判断** … 良い／悪い／危険／機会が一言である  
3. **指名された行動** … 医院名・町名・担当・期限のうち少なくとも1つがある  
4. **測り方** … やったあと「効いたか」を見る方法がある（特に施策）

現状：

| 条件 | 達成度 |
|---|---|
| 1 事実 | 高い |
| 2 判断 | 中〜高 |
| 3 指名 | **低い**（Phase 2 の町名、Phase 1 の表が例外） |
| 4 測り方 | Phase 5 のみ高い |

## 10. 改善の優先順位（ユーザー価値順）

工数の小さい順ではなく、**ユーザーが動けるようになる順**。

1. **結論ボックスの「次にやること」に、すでにある表の上位を指名で書く**  
   例：Phase 1「藤井クリニック・岸本クリニック…へ今月挨拶」／Phase 4「再来率下位○院経由の初回に声かけ試験」
2. **トップの「次にやること」を、各ページ要約から自動生成に寄せる**（直書き3行をやめる）
3. **地図に結論ボックスを足す**（どこが濃い／どこが空白か＋配布候補）
4. **Phase 3 のオープン層に「獲得候補医院」表を出す**（天井の数字の隣に置く）
5. **北川氏関心の年齢戦略（30代子持ち→60代慢性）を、ユーザー向け1ページまたはサマリー1項目にする**  
   いま画面に出ていない＝「データを見ても戦略仮説を検証できない」

やらない方がよいこと：

- 専門家向け折りたたみを最初から開く（数字が苦手な人向けというD案の狙いと逆）
- 手法名をユーザー層に戻す
- 分析をさらに増やすだけで画面の3段目を厚くしないこと

## 11. 結論（依頼への回答）

- **示唆の「型」は、ユーザー向けに用意できている。**  
  経営サマリー・結論ボックス・図の一言・専門家折りたたみ、の分離は正しい。
- **深いPython分析は、ユーザーには「結論の裏」として隠れている。**  
  それは失敗ではなく設計どおり。問題は、隠したあと表に出した結論が、まだ「方向性」止まりであること。
- **ユーザーにとって意味があるのは、理解できた先の指名された行動である。**  
  いま一番足りないのは分析の深さではなく、**すでに表にある具体名を、一番目立つ行に上げること**である。
